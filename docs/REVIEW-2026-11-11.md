## 2. Architecture — adversarial findings (ranked)

1. **"Memory" was not memory of people.** Episodic memory was per browser
   session/workspace; nothing about a *caller* survived a call, and there was
   no identity concept beyond bearer capabilities. The product name promised
   more than the system did. → P1 slice below.
2. **Two conversation pipelines still decide referents.** The contract runs in
   shadow; the legacy chain (`voiceQuestions` joining, regex follow-up,
   `grant.lastField`, post-hoc sentence deletion) still decides what "it"
   means on a call. Every referent bug lives in the path the docs call
   legacy. Cut-over needs divergence data from real calls; until then, treat
   referent quality as unmeasured.
3. **`server.mjs` (4.4k lines) and `voice-adapter.mjs` (2.1k) are closures,
   not modules.** The canonical resolver is only reachable from inside
   `createLocalServer`; this slice had to capture it from an object literal.
   Extract `answer({ scope, question, presentation }) → { final, corpus }` as
   the one service every surface calls (typed, voice, MCP, caller memory).
4. **Disclosure is so frequent it carries no information.** Coverage is
   "unverified" on ~100% of answers (no provider), plus a version banner on
   every demo answer ("external file edits aren't checked"), plus the status
   caveat. Users learn to skip all three, including the one that matters
   ("not approved"). Recommendation (owner decision, safety-relevant): issue a
   certificate for single-clause questions the closed grammar fully consumes,
   so "unverified" becomes the exception; show the version banner only when a
   version actually changed or for uploaded documents.
5. **CDN-cached GET `/answer`** is correct for anonymous demo answers and
   dangerous for anything personal. Caller memory is `no-store` and POST-only;
   keep a test that no personalised field ever appears on the GET path.
6. **Process-local state everywhere**: sessions, voice tombstones, replay sets,
   call maps. Single instance only. Durable caller memory needs a persistent
   disk; Render free tier is ephemeral.
7. **First-load budget headroom is 10 bytes** after the P0 fix, and `site.js`
   is a 113 KB monolith. Split answer rendering from landing chrome before the
   next feature, not after.

## 3. Component design (Linear / Cardboard bar)

- **Never block input.** The disabled-submit pattern was the root of a P0 bug.
  Pattern now: latest wins, coalesce duplicates, show progress in the result
  area (skeleton), not by disabling controls. The call page queues turns.
- **Answer before provenance.** The answer card stacks: version banner →
  verdict + answer → coverage block → "computed live" → four citations. Lead
  with verdict + answer; one citation (the line it rests on) visible; "3 more
  sources" collapsed.
- **Motion must not gate content.** Answer words start at opacity 0 and fade
  from blur (380 ms). Emil Kowalski's rule: animate feedback, not the thing
  the user is waiting to read. Recommend: render text immediately; keep the
  highlighter stroke as the only answer motion. The call page follows this
  (≤160 ms ease-out, reduced-motion respected, content first).
- **Keyboard.** No `/` to focus ask, no ↑ to recall the last question, no Esc
  to cancel. Cheap, high-signal.
- **Pilot path.** "Request a pilot" opens a GitHub issue — fine for
  developers, wrong for a support or ops buyer. And "Priced per verified
  answer; abstentions are free" reads as an established commercial term;
  label it as a pilot proposal or remove it until priced.
- **Positioning.** The hero ("The report changed. The answer shouldn't be a
  guess.") sells a verification engine for health records. The memory story
  (people + conversations + records) is absent from the first screen.

## 5. P2 — evaluation plan (not implemented here)

Independent authorship is the point, so it cannot be produced by the same
hands that wrote the code. Proposed protocol:

- **Authors:** two people who have not read the engine; written against the
  fictional corpora plus one unseen corpus; frozen before any tuning.
- **Coverage:** EN / HI / Hinglish × {direct, correction, negation, multi-turn
  referent, changed preference, source revision between calls, ambiguous
  identity, unsupported request, medical-memory attempt}.
- **Metrics, reported separately:** end-to-end wrong factual assertions
  (primary; target 0), correct-answer rate, safe-abstention rate, retrieval
  recall@k and top-1 (never reported as answer accuracy), caller-memory
  recall / update / deletion correctness, cross-caller leakage (target 0),
  p50/p95 first-audio and full-turn latency **on real calls** (local timings
  here — 35–111 ms per turn on the demo page — are not call latency).
- **Claims policy:** developer-written fixtures are regression tests, never
  accuracy claims.

## 7. First-visitor walkthrough (`/calls.html`, `VM_CALLER_DEMO=on`)

1. **Call one as Asha** (fictional). Tap the suggested line *"Please remember
   that I prefer Hinglish, and remember this conversation for next time."*
   → *Remembered* shows Language: Hinglish and consent.
2. Ask *"Was the revised fee approved?"* → spoken in Hinglish: "$42,000 sabse
   naya proposal hai, aur yeh abhi manzoor nahi hua hai." *Verified* shows
   the English admitted sentence, "Proposed, not approved", the Commercial
   Revision line and the source version. *Unresolved*: still not approved.
3. Try *"Remember that the fee was approved."* → refused: the documents
   decide. End the call.
4. **Call two.** Start again. Before you ask anything: "Welcome back. Pichli
   baar aapne fee ke baare mein poocha tha. Tab se documents nahi badle." —
   it knows who you are, what you asked, and it re-read the documents.
5. *"Please switch my language to English"*, then *"Forget my language
   preference"* → the *Remembered* panel and the stored-items ledger update.
6. **Switch to Ravi.** "I don't have anything remembered for you yet."

That is why it is called Voice Memory: it remembers the person and the
conversation, knows what changed in the record, and can prove what it says.
