Audited baseline: `35f9987e4b4cf499ba8e2f6533c7b23d19a64530`.

Local implementation and synthetic-fixture verification only; changes have not been deployed.

## Assessment

The application has substantial citation, clinical, isolation and parser checks, but its polished fictional cases hide important gaps in ordinary uploaded-document use. The highest-impact reproduced failures are lost workspace identity during temporary network failures, concurrent drops creating separate libraries, and generic prose producing retrieval chunks but essentially no connected graph. These are corrected on this branch. Generic paraphrase recall and durable workspace storage remain significant limitations. A connected structural graph alone does not make the answer engine understand paraphrases.

## Architecture direction

Keep one canonical document version as the source of offsets for chunks, records, graph evidence and voice citations. Persist document identity separately from content hash. An ingestion job should atomically publish a versioned bundle; partial text can be marked provisional, and consumers must never silently mix generations or workspaces.

For durable personal use, separate authenticated workspace metadata and ingestion-job state from original-file/object storage. Store canonical text, versioned chunks and exact spans with tenant/workspace/document/version keys, then derive structural graph edges and validated fact links. Reuse cached parses/embeddings only within a compatible parser/model version and explicit privacy boundary. Add idempotent job retries, deletion/retention behavior, restart recovery and bounded OCR workers before enabling more traffic. This branch does not provision infrastructure or migrate uploaded personal data.

For voice, bind the call to a server-owned workspace/version capability. Test an uploaded document with a unique synthetic fact through speech → transcript → scoped retrieval → validated citation → spoken response, including upload expiration, case switching, interruption and provider timeouts. Measure each latency segment. The present `scopeOf()` intentionally favors an existing upload even on demo tabs; this differs from some “open case” UI wording and needs an explicit product decision and matching tests.
