# Source-bound identifier answers

Identifier-value questions previously could return topical passages containing a different identifier. Regressions on `35f9987` reproduced an ordinary reference code being used for a booking reference, and an entry permit being used for a parking permit. These are wrong-field excerpt results, not evidence that the system invented a new identifier or read another workspace.

The identifier path binds the requested subject, qualified field and value in a declarative clause, a pipe-table field column and entity row, or an explicit `Entity: ...` key/value record. It preserves canonical offsets, source hash, full qualifying clauses and contiguous citation spans. Document-level draft/preliminary context in the first twelve parsed lines remains in the answer and citation. Explicit templates, fenced examples, quoted questions and instructions do not establish assigned identifiers.

Supported value questions use What/Which/Give/Show/Tell/Provide/List forms. Supported field labels include permit, license/licence, certificate, reference, serial, part, registration, tracking, booking, reservation, account, policy, ticket and application with number/code/ID labels. Qualifiers such as parking/entry and temporary/permanent stay distinct. Other intents, including price, status, approval and formatting, retain their existing routes. This is a bounded grammar; it does not provide general role, coreference, arbitrary document-layout or authority understanding.

Identifiers remain strings: leading zeros, case and padding are significant; numeric and slash-separated values are allowed only in a bound identifier field. A clock or nearby budget cannot supply the value. Distinct bound values remain unresolved; the lookup does not infer which source supersedes another. Exact repeated values agree. Explicit `not assigned` records remain visible with their status.

Canonical line/clause indexes use a WeakMap keyed by source object and guarded by the current text. There is no unbounded question cache or new provider dependency. More than 32 candidate facts or an over-8 KiB required citation context fails closed. Ambiguous table headers/target rows do not silently choose a column/value.

The engine, typed answer and streamed voice paths share the decision. Generic relevance, paraphrase and model rescue cannot replace a missing binding with another field. A local HTTP regression enables a fake semantic provider and opts in, then verifies zero provider method calls across seven synthetic typed/voice scenarios. No real microphone, voice platform or paid provider was used.

Qualification receipts are local under `audit/20261106-identifiers/`. The original-base full run passed 759 Node tests, 131 ingestion checks, keyword retrieval and vault checks; it stopped at the existing hardcoded Linux Chrome executable on this Mac. The candidate is subsequently stacked on PR #57, which contains portable browser tests and the workspace/cache/voice boundary repairs. Integrated qualification is reported in the PR; do not treat the earlier platform failure as a passing complete run. General event-start paraphrases and durable storage remain separate work.
