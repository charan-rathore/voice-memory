Memory your voice agent can prove.

Voice Memory gives a voice agent persistent, caller-controlled memory and keeps it apart from what the documents say now. A returning caller is recognised; what they asked last time is rechecked before anyone repeats it.

Try the two-call demo Integration guide (API v1)

What is Voice Memory?

A service your voice agent calls at the start of a call and on each turn. It returns what this caller asked to be remembered, what they asked before, and a current answer from the documents that apply to them, with the line it rests on.

Why can't the agent just remember in its prompt?

In a prompt, last month's answer, a caller's claim ("it was approved") and the current record are all just text. Voice Memory stores them as different kinds of data, re-derives facts every call, and never lets a remembered statement change a verdict, an approval or a document version.

How does caller identity work?

Your backend authenticates the caller (login, OTP, SSO) and signs a short-lived, single-use assertion. A phone number or caller ID is never enough. Inbound calls start unverified with no memory until your backend confirms the caller.

What is stored?

PreferencesLanguage and answer length, only when the caller asks. 365 days.
ConversationEach completed turn: the question, the verified outcome, the source version and cited lines, and what was actually said. 90 days.
Open requests"Tell me when it's approved." Open until the caller or your team closes it. 90 days.

What is never stored without consent?

Conversation history (episodes, subjects, requests) needs the caller's consent. Health and medical details are never stored as preferences. Account ids are hashed. A caller's claim about the record is refused, not stored.

What happens when a document changes?

On the next call every remembered subject is asked again against the documents that apply to that caller now. The response says whether the source changed, whether a different policy version now applies, and why the answer changed. If applicability is unknown, the agent is told to ask, not guess.

How are memories corrected and deleted?

By voice ("switch my language to English", "forget everything") or by API. Deletion removes the stored data immediately. Every change returns a signed receipt. Disk snapshots can bring back data deleted after the snapshot, so a restore needs a deletion replay (documented, not automated).

Which voice platforms can use it today?

Bolna, through its custom-LLM setting and call variables (built and tested against Bolna-shaped requests), and any stack that can call the provider-neutral HTTP API from its own backend. No real Bolna call has been placed yet. The two-call demo is a typed simulation through a demo API: it uses the same document resolver as a voice call, but not the voice provider's path, speech or telephony.

What latency does it add?

Measured locally on a small fictional policy (no network, no telephony): p95 about 1 ms to start a call, under 4 ms to recall and recheck, under 4 ms for a source-verified answer. Real-call first-audio latency has not been measured.

How do I test it with my own synthetic documents?

Run node examples/client/returning-caller-demo.mjs to see three calls locally, then point the example client at a staging server with your own fictional documents. Don't use real customer data in a pilot until production readiness is complete.
